Input requirements

Normalized records require tenant, event_id, timestamp (with time zone), principal, resource, action, public_access, unusual_region and large_read. Indicators are the integers 0 or 1. JSON files contain an object with an events array. Limits: 16 MiB and 10,000 records per import.

Provider logs (AWS CloudTrail, Azure Monitor resource logs, Google Cloud Audit Logs and OCSF API Activity) are converted by built-in adapters. Each original provider event is preserved in the signed evidence. Upload exported files; live cloud connections are not configured.

Workflow guide

Investigation workflow

  1. Import. Upload normalized records or a provider log export, with an optional permission policy.
  2. Triage. Select an incident and review its risk score, score breakdown, ATT&CK context and event timeline.
  3. Assess. Record a conclusion (expected activity, more evidence required or suspected threat) with a rationale.
  4. Respond. Preview a response permitted by the policy, record approval, apply the change through your change process and record the outcome.
  5. Close and export. Close as expected, resolved or escalated, then export the signed investigation archive.

Scores come from a transparent, configured profile rather than a trained model. Evidence is signed with a local software key. Analyst names and change outcomes are self-asserted. This application never changes cloud resources.
